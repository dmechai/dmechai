# Profile README maintenance

Edit `README.md` directly for the introduction, contact links, and technology list. Keep any technology heading and dividers inside the `tech-stack` markers so the section stays invisible when empty. The profile repository must remain public and match the current GitHub username for GitHub to display it on the profile. No CMS is required.

The host timer `dmechai-profile-stats.timer` runs daily at 04:08 UTC. Its `gh` credentials need read access to the intended repositories and write access to the public profile repository. On each run the publisher resolves the current login from the authenticated GitHub account, verifies the exact public, non-fork `login/login` repository and targets its `main` branch. After a username change, rename the existing profile repository on GitHub to match; the publisher will pick up the new name without a script edit. If the target is missing or invalid, the run stops without publishing. It publishes only aggregate counts and percentages in the `fun-facts` block, retrying on concurrent edits. The same run refreshes the contribution graphic from complete current-branch history for the latest 53 UTC weeks. It does not publish repository names, links, IDs, or per-repository activity. Commit counts cover all commits reachable from current branches, deduplicated within each repository. Language coverage uses the GitHub languages endpoint and counts a repository once per detected language or file type. Percentages use all eligible repositories as the denominator, do not sum to 100%, and can imply the repository total even though it is not printed. The top ten are visible and the remainder are folded. Forks and the profile repository are excluded from both charts. Empty datasets retain a no-data message. Publishing totals makes them public, and Git history can retain old totals.

Install `owned-stats.mjs`, `contribution-snake.mjs`, and `publish-owned-stats.sh` in `/usr/local/libexec/dmechai-profile` and the matching unit files in `/etc/systemd/system`. Reload systemd and enable the timer. Run `systemctl start dmechai-profile-stats.service` for an immediate refresh.

The `Refresh featured projects` workflow runs daily at 04:43 UTC or via **Run workflow**. It selects up to six owned public, non-fork repositories. Other repositories are ranked by stars, forks, and name. The profile repository fills the last slot only when fewer than six other eligible repositories exist. Projects fill a left-aligned table from left to right, two per group, with up to three groups and no boxes for unoccupied slots. Each card uses one bordered cell for its linked title, optional short description, optional feature list and badges. Feature bullets use the same baseline as their text. Each row has its own table body to avoid alternating shaded rows on GitHub. Each card can show up to three flat-square badges, prioritizing nonzero stars and forks, the primary language, SPDX license, confirmed profile features and public repository topics. Missing facts are not invented. The workflow runs `node tools/featured.mjs "$PROFILE_OWNER" repos.json` to update the block and download actual Shields.io `flat-square` SVGs into `assets/featured/`. Profile visitors load the checked-in copies from GitHub. The workflow reuses badges whose URLs are unchanged and uses `curl` to download new ones; a failed download stops the refresh before writing any changes. Public About descriptions take precedence over the profile repository's built-in one-sentence summary. Each refresh reads the selected public repositories' default-branch READMEs. To publish or update feature bullets, add a block with up to two plain-text Markdown bullets of up to 120 characters; bullets outside the block are ignored. The profile and Oriel NFT cards have verified fallback bullets when there is no block. Other projects without a block omit the bullets.

```markdown
<!-- featured-highlights:start -->
- First feature.
- Second feature.
<!-- featured-highlights:end -->
```

Private repositories cannot be selected. The former scheduled snake workflow no longer overwrites the graphic; the host timer owns both SVG files. The snake follows orthogonal paths toward the nearest remaining contribution square, crosses empty squares only to get somewhere, and clears each active square on first arrival. Reduced-motion viewers see a static calendar. Run `node --test tools/*.test.mjs` to check the cards, charts and SVG generation.
